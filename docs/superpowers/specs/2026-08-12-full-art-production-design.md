# 《渊海录》全量角色与场景美术生产设计

> 日期：2026-08-12  
> 状态：已确认  
> 目标分支：`main`

## 1. 背景与目标

当前烟柳镇 Demo 的玩法链已经可以运行，但 `DemoSceneGenerator` 仍在运行时创建纯色 `Texture2D`，玩家、NPC、敌人、建筑、树木和地面因此表现为色块。仓库内已有的主角精灵和烟柳镇 Tileset 也没有被场景生成器引用。继续扩展剧情和后台系统会放大返工，因此项目优先级改为全量美术资产生产与 Unity 场景接入。

本阶段的完成目标是：以完整俯视 2D 像素路线制作当前剧情范围内的全部角色和全部命名区域，使项目从色块功能原型变为可持续扩展的像素武侠世界。完成前不扩展新的后台玩法，只保留美术接入所需的最小代码适配。

## 2. 已确认决策

- 渲染路线：完整俯视 2D 像素，不切换 HD-2D，不引入 3D 环境生产线。
- 角色规格：所有场内角色统一为 `32×32` 像素帧。
- 玩家体系：男女外观 × 六职业，共 12 套完整玩家资源。
- 场景范围：剧情文档中的全部命名地点独立制作，不仅限六大核心区域。
- 生产方式：模块化母版生产，导入 Unity 前烘焙成独立精灵表；运行时不逐层拼装。
- 正式资源缺失时阻止场景生成，不再回退到色块占位图。
- 所有完成内容最终提交到 `main`，并同步更新项目记忆与交接文档。

本规格是当前美术生产的最高优先级依据，并明确替代 `docs/01-art-style-guide.md` 中的 HD-2D 推荐、48×48 主角规格，以及 `AGENTS.md` 中沿用的 48×48 角色帧说明。实施阶段必须同步修订这些旧描述，避免双重标准。

## 3. 范围边界

### 3.1 玩家角色

六职业为剑客、拳师、暗器、医者、书生、异人。每个职业各有男性和女性版本，共 12 套。

每套玩家角色包含：

- 四方向待机，每方向 4 帧。
- 四方向行走，每方向 6 帧。
- 四方向冲刺，每方向 4 帧。
- 四方向普通攻击三连段，每段每方向 4–6 帧。
- 每职业至少 2 套职业招式动画。
- 受击、闪避、倒地和死亡动画。
- 与攻击判定帧对齐的动画事件。

### 3.3 通用 NPC、敌人与 Boss

- 36 套普通 NPC 基础形象：按六大核心区域分别覆盖官员、商贩、村民、军士、僧道、帮派等身份。
- 24 套区域敌人：六大区域各 4 套，名单固定为：
  - 天枢城：黑市打手、影楼刺客、腐化禁军、宫城追兵。
  - 苍岳峰：山道悍匪、叛门弟子、石阵傀儡、古刹破戒僧。
  - 烟柳镇：河盗、水匪、走私客、叛军水兵。
  - 赤砂关：北狄骑兵、沙匪、巨蝎、古墓守卫。
  - 幽篁谷：毒虫、蛊控村民、禁术兵、竹林刺客。
  - 寒渊岭：雪狼、猎人匪徒、冰墓守卫、叛军追兵。
- 10 套 Boss 形象：赫连北冥、柳含章、凤三娘、序章黑衣统领、天枢黑市之主、苍岳叛门掌门、烟柳叛帮首领、赤砂北狄先锋、幽篁禁术师、寒渊雪域巨兽。
- 所有角色仍使用 32×32 帧格；Boss 通过剪影、武器、披风、光环和大范围特效建立压迫感，不改变场内比例。

动作按用途配置：

- 核心同伴、反派、敌人和 Boss：待机、四向移动、攻击、技能、受击、死亡。
- 普通 NPC：待机、四向移动、对话和表情动作。
- 不会参与战斗的 NPC 不制作无效连招。

### 3.5 通用室内与地下套件

通用套件覆盖：客栈、民居、商铺、药铺、书院、衙门、宫殿、寺庙、洞穴、古墓、地牢、军营、船舱。相同结构可以复用，但区域配饰、材质纹理和地标不得只通过整体换色冒充独立场景。

### 3.6 非目标

- 本阶段不把项目迁移到 URP 或 3D。
- 本阶段不新增剧情章节、任务系统能力、商店系统能力或战斗机制。
- 本阶段不制作尚未出现在当前文档中的独立命名角色。
- 本阶段不采购或依赖运行时在线生成资源。

## 4. 视觉规范

### 4.1 基础参数

- 内部分辨率：`480×270`。
- Pixel Perfect Camera：开启。
- 角色帧：`32×32`。
- 基础 Tile：`16×16`。
- Pixels Per Unit：`16`。
- Filter Mode：Point。
- Compression：None。
- 抗锯齿：关闭。

### 4.2 角色可读性

- 缩放到实际游戏尺寸后仅凭剪影可以判断职业或阵营。
- 武器与关键配饰适当夸张，但不能越过统一帧锚点造成动画漂移。
- 使用选择性描边、成组像素块和有限色阶，禁止以纯色矩形、圆形或随机噪点作为正式造型。
- 男女版本共享动作节奏和锚点，但轮廓、发型与服装剪裁必须可区分。

### 4.3 职业动作语言

- 剑客：飘逸位移、剑弧、白蓝冷色。
- 拳师：重心下沉、近身爆发、红橙暖色。
- 暗器：侧身投射、残影、黑紫配色。
- 医者：银针、药葫芦、治疗手势、绿白配色。
- 书生：书卷、毛笔、墨气、青棕配色。
- 异人：符箓、罗盘、五行术式、紫金配色。

### 4.4 区域视觉语言

- 烟柳镇：青瓦白墙、河网、石桥、乌篷船、柳树、荷塘。
- 天枢城：城门、朱墙、坊市、主街、书院、衙署、宫城远景。
- 苍岳峰：山道、石阶、悬崖、云海、古刹、论剑台。
- 赤砂关：沙丘、峡谷、烽火台、城塞、驿站、商队营地。
- 幽篁谷：多层竹林、溪流、雾气、毒沼、机关、禁术营地。
- 寒渊岭：积雪、冰湖、温泉、猎人村、冰洞、雪峰古墓。
- 序章村庄：朴素农居、铁匠铺、田地，并提供焚毁状态。
- 落渊城：东都街区、城郊村落和主线逃亡路线。
- 绝云峰：剑派山门、练剑坪、索桥、峰顶。
- 镇岳山：碑林、祭坛、军寨、封禅遗迹。

## 5. 生产架构

### 5.1 模块化角色母版

角色源文件由体型、肤色、脸型、发型、服装、武器和配饰图层组成。所有图层共享方向、帧序、脚底锚点、手部锚点和武器锚点。模块化只存在于源资源和编辑器生产阶段；烘焙结果是每个角色独立的 PNG Sprite Sheet。

目录约定：

```text
Assets/ArtSource/Characters/
  Bodies/
  Faces/
  Hair/
  Outfits/
  Weapons/
  Accessories/
  Manifests/

Assets/Art/Characters/
  Player/
  Named/
  NPC/
  Enemies/
  Bosses/
```

源图层使用透明 PNG 与版本化清单文件，避免依赖专有编辑器格式才能重建。

### 5.2 模块化场景套件

场景源资源分为公共结构、区域专属 Tileset、区域大物件和独立地标。公共结构负责碰撞和连接规则；区域套件负责最终视觉。每个区域拥有独立资源 ID 和目录。

```text
Assets/ArtSource/Environment/
  Shared/
  Regions/<region-id>/
  Interiors/<interior-id>/
  Manifests/

Assets/Art/Environment/
  Regions/<region-id>/
  Interiors/<interior-id>/
```

### 5.3 Unity 资源目录

- `CharacterArtCatalog`：用稳定 ID 管理玩家组合、命名角色、NPC、敌人和 Boss。
- `EnvironmentArtCatalog`：管理区域 Tileset、建筑、植被、地标、天气和室内资源。
- 统一基础 Animator Controller：定义状态和参数。
- Animator Override Controller：为不同角色替换动画剪辑。
- 区域场景配置：记录资源目录、地图布局、入口、出口、地标、碰撞和天气。

## 6. 数据流与场景生成

```text
透明 PNG 图层 + 角色/场景清单
→ 编辑器烘焙与校验
→ 独立 Sprite Sheet / Tileset
→ 自动切片
→ AnimationClip / Animator Override Controller / Prefab
→ CharacterArtCatalog / EnvironmentArtCatalog
→ 区域场景生成器
→ 可保存、可重新打开的 Unity 场景
```

地图使用 Tilemap 分层：

1. Ground
2. Water
3. Lower Environment
4. Buildings
5. Character（Y 轴排序）
6. Foreground
7. Effects

建筑屋顶、树冠和桥拱的下半部分参与碰撞，上半部分进入 Foreground 遮挡角色。道路、门口、桥梁、室内入口和剧情触发点必须保留稳定锚点。

`DemoSceneGenerator` 和后续区域生成器不得在正式角色或环境上调用 `new Texture2D`。现有运行时色块代码在首批正式资源接入后删除。

## 7. 错误处理

- 清单引用的资源不存在：中止烘焙或场景生成，并报告稳定资源 ID 与预期路径。
- 图片尺寸、透明通道、PPU 或导入设置错误：中止生成，并给出实际值和要求值。
- 动画帧数或帧序错误：不生成对应 AnimationClip。
- 角色锚点缺失：不生成角色 Prefab。
- 场景地标、入口或出口缺失：不保存场景。
- 运行时不创建彩色方块作为降级资源；缺失项必须在编辑器阶段暴露。

## 8. 交付顺序

美术阶段连续执行，中途不切回新玩法开发：

1. 建立统一调色板、角色母版、Tile 规范和自动烘焙工具。
2. 完成 12 套玩家资源及全部动作。
3. 完成当前命名角色、36 套普通 NPC、24 套敌人和 10 套 Boss。
4. 完成十套室外区域和通用室内、洞穴、地牢组件。
5. 生成全部 Unity 场景，接入动画、碰撞、遮挡、天气和昼夜表现。
6. 统一视觉复核并修复比例、排序、切片、碰撞与动画问题。
7. 更新 `AGENTS.md`、记忆文档和交接文档，并提交到 `main`。

第 1 步允许先制作一套完整参考角色和烟柳镇参考画面，用于校准母版与调色板；它只是质量门，不改变“完成全量美术后再扩展玩法”的顺序。

## 9. 验收标准

### 9.1 自动验收

- 所有资源 ID 均可解析，不存在丢失引用。
- 所有正式图片符合尺寸、PPU、Point Filter、Compression 和切片要求。
- 12 套玩家动画完整，攻击事件与判定帧一致。
- 十个区域均可批量生成、保存、关闭并重新打开。
- EditMode 和 PlayMode 测试通过。
- 正式场景生成器不存在角色、建筑、地面或装饰的占位 `Texture2D` 生成代码。
- Unity Console 为 0 error。

### 9.2 人工验收

- 每个角色在预览场景播放其动作清单，无抖动、错位或武器漂移。
- 男女版本和六职业在实际缩放下可通过剪影辨认。
- 每个区域完整走通一次，入口、桥梁、室内和地图边界无卡死。
- 每个区域至少三个地标可以在截图中直接识别。
- 固定机位截图检查画面层次、区域辨识度、角色可读性和前景遮挡。
- 从主菜单进入游戏后显示正式角色和完整场景，不出现色块 Demo。

## 10. 文档与版本控制

- 所有生产工具、清单、源图层和 Unity 成品资源纳入 Git。
- `Library/`、`Temp/`、测试日志和可重复生成的临时预览不纳入 Git。
- 每个资产批次提交前更新完成清单。
- 阶段完成时更新 `AGENTS.md` 和交接文档，记录目录、生成命令、验证结果、已知限制和下一阶段入口。
- 所有最终提交位于 `main`。
