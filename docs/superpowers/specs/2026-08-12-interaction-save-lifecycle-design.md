# 交互、存档与场景生命周期收口设计

## 目标

补齐当前未提交的玩家交互与存档改动，并修复巡检发现的关联问题，使新游戏、读档、场景初始化、装备属性恢复和现有 Demo 场景之间形成一致的数据流。

## 非目标

- 不实现活跃任务持久化；该能力依赖稳定的任务数据库资源。
- 不持久化尚无正式数据来源的世界敌人、拾取物与区域标志。
- 不制作 Animator、美术、音频或新地图内容。
- 不重构为独立存档服务，也不改变 PlayerPrefs + JSON 的现有存储介质。
- 不推送远端或发布构建。

## 已确认根因

1. `IInteractable` 已存在，但没有玩家侧调用者；新增组件目前只由场景生成器挂载，已保存的 Demo 场景不会自动获得它。
2. `SceneDirector` 在每次进入 Demo 后固定初始化玩家属性、位置、初始武学和物资，无法区分新游戏与读档，因而会覆盖或追加读档结果。
3. `SaveManager.LoadGame` 使用匿名 `sceneLoaded` 订阅且不解除，后续加载任意场景时会重复应用旧存档。
4. 当前存档保存角色派生总属性，背包恢复装备 ID 后又缺少一致的装备加成重算语义，卸下装备时可能得到错误属性。
5. 主菜单序列化的首场景名为 `YanLiuTown`，实际 Build Settings 中只有 `Demo_YanLiuTown`。
6. 新增脚本尚无 `.meta`；输入配置修改后还需要重启 Unity 才能被编辑器重新加载。

## 推荐架构

### 1. 显式场景进入模式

在 `GameManager` 中增加轻量的场景进入上下文，至少区分：

- `NewGame`：允许 `SceneDirector` 执行出生、初始属性、初始物资、初始武学和教学对话。
- `LoadGame`：`SceneDirector` 跳过上述新游戏初始化，由 `SaveManager` 恢复数据。
- `SceneTransition`：保留玩家持续状态，仅执行场景展示类逻辑。

直接从 Unity 编辑器运行 Demo 场景时默认按 `NewGame` 处理，以保持现有开发体验。主菜单的新游戏按钮显式设置 `NewGame`；读档前显式设置 `LoadGame`。存档恢复结束后，上下文回到普通运行态，避免污染下一次场景加载。

### 2. 单次、可解除的读档回调

`SaveManager` 不再注册匿名 lambda。加载前将反序列化结果保存为待恢复数据，注册具名 `OnSceneLoadedForLoad`；回调执行时先解除订阅，再恢复玩家和全局系统。重复调用读档时先清理旧订阅，保证最多只有一个待处理读档。

加载顺序固定为：

1. 读取并校验存档。
2. 设置 `LoadGame` 进入模式并加载目标场景。
3. 恢复玩家身份、等级、经验、基础战斗属性和当前资源。
4. 恢复背包、装备和金钱，并据装备重新计算派生属性。
5. 恢复武学及其装备槽。
6. 恢复已完成任务。
7. 设置游戏状态为 `Exploration`，结束读档上下文。

### 3. 基础属性与装备恢复

存档新增版本号，并保存 `CharacterStats` 的基础攻击、防御、敏捷、最大生命和最大内力，不再把含装备加成的派生总值当作基础值。

`InventoryManager.LoadSaveData` 在恢复所有槽位与装备 ID 后调用统一的装备属性重算。旧版存档没有背包内容，因此按原有总属性恢复为基础属性，不额外叠加装备，从而保持兼容。

加载方法需对缺失数组、数组长度不一致、未知物品或武学 ID 做空安全处理。未知数据跳过并记录警告，不应阻断整份存档恢复。

### 4. 交互系统接入

保留 `PlayerInteraction` 的最近目标策略和 `GameManager.CanPlayerAct()` 输入门：

- K 为主键、E 为备用键。
- 每隔短时间扫描附近 `IInteractable`，选取最近且 `CanInteract()` 的目标。
- NPC、传送点、可破坏物和需要按键的事件触发器共用同一接口。
- 自动触发型 `EventTrigger` 不显示交互提示。

接入点包括：

- `DemoSceneGenerator` 创建玩家时挂载组件。
- `SceneBootstrapper` 创建或接管玩家时确保组件存在。
- `SceneDirector` 对既有 Demo 场景中的玩家执行一次幂等保障，避免必须重新生成场景才能测试。

新增脚本的 `.meta` 必须纳入版本控制。

### 5. 主菜单与场景名

`MainMenu` 默认首场景及现有 `MainMenu.unity` 的序列化值统一改为 `Demo_YanLiuTown`。开始新游戏前设置进入模式，并清理可能残留的运行时数据，防止在同一编辑器会话中重新开始时继承旧背包或任务状态。

## 错误处理与兼容

- 无存档、JSON 无法解析、目标场景为空或目标场景不存在时，不注册加载回调，不切换进入模式，并输出明确错误。
- 玩家或必要组件缺失时，仅跳过对应子系统并记录错误；回调仍需解除，避免永久污染后续加载。
- 存档版本缺失视为旧版；旧版字段继续保留读取路径。
- 加载背包前先清空全部槽位，避免较短旧数组留下当前会话残余数据。
- 读档完成后刷新背包事件和装备属性，保证 HUD/菜单订阅者得到一致状态。

## 测试与验证

项目已安装 Unity Test Framework。新增 EditMode 测试时优先覆盖纯数据和幂等行为：

- 已完成任务加载会去空、去重并替换旧列表。
- 武学加载能清空旧槽位，忽略未知 ID 和空数组。
- 背包加载会清空残余槽位，并能恢复装备 ID、金钱及触发属性重算所需状态。
- 场景进入模式只允许新游戏初始化，读档模式会跳过。
- 读档回调在单次使用后解除；重复发起读档不会叠加订阅。

静态验证包括 C# 编译、Unity 测试、`git diff --check`、场景名和组件接入检索。人工 Play 验证清单：

1. 主菜单点击新游戏能够进入 Demo。
2. 靠近 NPC 显示提示，K/E 均可开始对话。
3. 自动事件不显示提示，按键事件可触发且一次性事件触发后提示消失。
4. 保存后改变位置、属性、背包、装备、武学和已完成任务，再读档能精确恢复。
5. 读档不会重复获得初始物资，也不会被重置到新游戏出生点。
6. 读档后卸下/更换装备，角色属性变化正确。
7. 再次切换场景不会重新套用上一次存档。

## 验收标准

- 新游戏与读档初始化互不覆盖。
- 读档最多注册一个、只执行一次场景回调。
- 现有 Demo 场景无需重新生成即可使用 K/E 交互。
- 背包、装备、金钱、武学和已完成任务能够往返保存；装备属性在读档后可正确卸下与更换。
- 主菜单能够加载实际 Demo 场景。
- 新增测试通过，Unity 工程无编译错误；如本机无法启动 Unity，必须明确报告未执行项并提供人工验证清单。
- `AGENTS.md`、`README.md`、`SETUP_GUIDE.md` 与实际实现一致。
