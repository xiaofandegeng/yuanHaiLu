# 单男主角试玩版设计规格

## 目标

将《渊海录》收缩为一个可在 10–15 分钟内完整体验的武侠 RPG 垂直切片：固定男性主角、三种可选择的武器流派、烟柳镇与客栈，以及一条从接取到交付的任务闭环。当前目标是证明核心体验，而不是生产大世界内容。

## 产品决定

- 主角固定为男性，正式运行时美术 ID 固定为 `player_male_swordsman`；不再向玩家展示性别、职业或服装选择。
- 开局只选择武器流派：`sword`（剑）、`gauntlets`（拳套）、`dart`（暗器）。三种流派共享同一男性身体、四方向动作和基础动画；只改变武器小图、攻击判定、一个主动技能、数值倾向和小型特效。
- 新游戏与旧存档都规范为男性主角。存档升级到 v5，新增稳定的 `weaponStyleId`；v1–v4 存档迁移为 `sword`，保留其既有任务、背包、等级和位置数据。
- 试玩版只包含主菜单、烟柳镇和客栈室内。河岸战斗区属于烟柳镇的可达子区域，不新增独立大地图。

## 试玩体验

玩家从主菜单选择武器流派，进入烟柳镇的客栈前。客栈掌柜交付“河岸失物”任务：前往河岸、战胜两名拦路敌人、取得任务物、返回客栈交付奖励。试玩过程必须覆盖移动、交互、对话、一次战斗、奖励、场景进出与存档。

| 流派 | 普攻与定位 | 主动技能 | 美术范围 |
|---|---|---|---|
| 剑 | 中距离、均衡三连击 | 前方剑气 | 剑与剑气小特效 |
| 拳套 | 近距离、快速连击 | 短距冲拳 | 拳套与命中火花 |
| 暗器 | 远距离、较低近战伤害 | 三枚扇形飞镖 | 飞镖与轨迹小特效 |

## 范围

### 本期保留

- 一个男主角、三种武器流派。
- 烟柳镇主街、河岸战斗点、客栈室内。
- 客栈掌柜、河岸引导 NPC、两种敌人和一个任务物。
- 对话、任务、战斗、掉落/奖励、暂停与存档。
- 主菜单 → 烟柳镇 → 客栈 → 河岸 → 客栈的可操作流程。

### 明确冻结

- 其余 11 套主角外观、85 名非试玩角色、10 个大区域、其余 12 个室内与全量美术生产。
- 商店、技能树、小地图、BOSS 战、完整剧情章节、世界状态持久化和全区域传送网络。
- 新的运行时生成精灵、3D/URP/后处理，以及 `ProjectSettings/` 平台改动。唯一例外：`EditorBuildSettings.asset` 的场景清单允许注册试玩场景 `Demo_Inn`；除此之外任何 `ProjectSettings/` 文件零变更。docs/17 另批准**两处 Demo 的原生像素美术返工**：固定男主源帧、烟柳镇/客栈的三层背景和掌柜/两名水匪/荷包静态精灵；不得扩展到正式区域、正式 NPC/敌人/Boss 或其 Prefab/Controller。

冻结内容保留在仓库中，不删除、不重命名、不合并至本期资产目录。

## 运行时与数据边界

### 身份与存档

- `PlayerAppearance` 不再代表可选择的游戏玩法身份；菜单不调用 `SelectAppearance`。
- `GameManager.PlayerArtId` 在新游戏和迁移后恒为 `player_male_swordsman`，`PlayerAppearanceBinder` 仍使用现有方式将该固定美术应用到玩家。
- 新增 `WeaponStyleId`（`sword`、`gauntlets`、`dart`）作为独立于美术的运行时/存档字段。非法、缺失或旧版值一律安全回退到 `sword`。
- v5 读档恢复顺序：读取存档 → 规范固定男主与武器流派 → 载入场景 → 恢复角色状态、位置、背包、任务 → 进入 Exploration。禁止读档重新发放初始物资或覆盖位置。

### 菜单与战斗

- 主菜单只有“新游戏”“继续游戏”和三种武器流派按钮；选择时显示武器名称、短定位说明与同一男主预览，不能显示职业/性别网格。
- `PlayerCombat` 和 `MartialArtsSystem` 以 `WeaponStyleId` 决定攻击范围、冷却、命中方式与主动技能；角色身体动画保持共用。
- 武器切换只发生在新游戏菜单和存档恢复，不在试玩过程中提供复杂的装备/职业切换 UI。

### 场景与任务

- `MainMenu` 只进入 `Demo_YanLiuTown`；Build Settings 的 MVP 构建要求 MainMenu、Demo_YanLiuTown、Demo_Inn 可用。两个 `Demo_*` 场景从冻结基线 `Regions/yanliu`、`Interiors/inn` 克隆装配，基线场景文件本身不变。
- 烟柳镇到客栈的入口、客栈返回烟柳镇的出口和河岸战斗点必须各有明确的可达锚点与碰撞边界。
- 试玩任务只用一个稳定 ID，进度顺序固定为 `talk_to_innkeeper` → `reach_riverbank` → `defeat_river_enemies` → `collect_lost_item` → `return_to_innkeeper`。每步只在真实成功行为后推进，重复触发不得重复计数。

## 美术与关卡原则

- 男主先通过 `docs/14-gate-a2-visual-reference-board.md` 的“比例标准页 + 三张 ≤160×90 缩样”审查，再重画任何 480×270 关键帧；未批准前不得拆 Tile 或批量制作。
- 烟柳镇只完成一条可走主路、一个河岸战斗点和客栈入口，围绕可玩路线构图；客栈只完成入口、柜台、桌席、后厨、楼梯和床位所需区域。
- 所有画面继续遵循墨骨、青碧、赭石、朱砂的视觉规则；自动像素检查只能辅助，1× 画面由人工验收。

## 验收标准

1. 新游戏只有剑、拳套、暗器三种选择，选择后始终显示同一男性主角。
2. 三种选择分别产生可观察的攻击距离/命中方式/主动技能差异，且不会改变主角身体美术；武器小图（菜单图标与角色随身武器层）随流派真实切换。
3. 从主菜单出发，可无控制台错误地完成客栈接任务、河岸战斗与拾取、返回交付、保存、退出后继续游戏。
4. v1–v4 存档迁移后为男主 + `sword`，且保留可恢复的既有游戏进度；非法 `weaponStyleId` 安全回退。
5. 试玩内容不依赖冻结区域、冻结角色或批量美术生成；`ProjectSettings/` 除 `EditorBuildSettings.asset` 场景清单注册 `Demo_Inn` 这一处例外之外零变更。
6. 自动验证至少覆盖菜单选择、存档迁移、三种武器判定、任务顺序、场景往返；人工验证覆盖三种流派各一次完整试玩。
7. 对相对 `main` 的最终变更运行 `git diff --check` 为零输出；合并和推送仍需用户单独授权。

## 风险与非目标

- 三种武器共用身体动画会让姿势差异受限；本期以武器层和命中/特效差异建立玩法辨识，不扩展新的角色骨架或职业动作集。
- 现有 12 外观、97 角色和 23 环境是历史资产；它们可继续保留用于以后评估，但不代表试玩版承诺。
- docs/17 已在 MVP 限定范围内批准美术返工：`player_male_swordsman` 的可动画源帧、`Assets/Art{Source}/Environment/MVP/v2/` 下两处场景的 `Ground/Environment/Foreground` 原生像素层，以及 `Assets/Resources/Art/MVP/` 下掌柜、两名水匪和荷包的 32×32 持久精灵。此前 7 张功能小图（weapon_sword/gauntlets/dart、proj_qi/proj_dart、loot_gold/loot_item）继续保留。它们都由持久资产加载、禁止运行时生成；正式角色、环境与批量美术流水线仍全部冻结。
